# Feature Specification: AI面试复盘网站

**Feature Branch**: `001-interview-review`

**Created**: 2026-07-05

**Status**: Draft

**Input**: 用户描述：通过AI对话方式进行面试复盘，系统包含复盘点管理、每日考核、技能管理、数据导出等功能

## Clarifications

### Session 2026-07-05

- Q: 系统是否需要用户登录认证？ → A: 需要用户密码，做好数据隔离
- Q: AI服务调用失败时如何处理？ → A: 同时支持手动输入答案和AI生成答案
- Q: Markdown导出的范围是什么？ → A: 支持单个复盘点单独导出为独立MD文件
- Q: 每日考核和练习题的触发时机是什么？ → A: 用户登录或访问页面时按需生成
- Q: 周度分析报告应包含哪些内容？ → A: 分类分析：按技能分类统计 + 薄弱点识别 + 改进建议

## User Scenarios & Testing *(mandatory)*

### User Story 0 - 用户登录认证 (Priority: P1)

用户通过用户名和密码登录系统，系统验证身份后允许访问个人数据。不同用户的数据完全隔离，互不可见。

**Why this priority**: 数据隔离是系统安全的基础，必须在其他功能之前实现

**Independent Test**: 可以通过创建两个用户，验证各自只能看到自己的数据

**Acceptance Scenarios**:

1. **Given** 用户在登录页面, **When** 输入正确的用户名和密码, **Then** 成功进入系统主界面
2. **Given** 用户输入错误的密码, **When** 点击登录, **Then** 显示错误提示并拒绝访问
3. **Given** 用户A已登录并创建复盘点, **When** 用户B登录, **Then** 看不到用户A的任何数据
4. **Given** 新用户, **When** 点击注册, **Then** 可以创建新账号

---

### User Story 1 - 创建面试复盘点 (Priority: P1)

用户在面试后，通过与AI对话的方式记录面试问题。用户输入面试官提出的问题后，可以选择两种方式获取答案：
1. 调用AI生成详细的答案回复（包含技术解答和在线资料链接）
2. 手动输入自己的答案

每个复盘点以问答对形式存储，答案来源会标记为"AI生成"或"手动输入"。

**Why this priority**: 这是系统的核心功能，没有复盘点创建能力，其他功能无法运作

**Independent Test**: 可以通过输入一个面试问题，验证系统返回包含答案和链接的完整回复

**Acceptance Scenarios**:

1. **Given** 用户在对话框输入面试问题, **When** 选择"AI生成答案", **Then** 系统返回AI生成的答案，包含技术解答和参考资料链接
2. **Given** 用户在对话框输入面试问题, **When** 选择"手动输入答案", **Then** 用户可自行编写答案并保存
3. **Given** 用户输入问题后, **When** 答案确认保存, **Then** 问答对自动保存到复盘点列表，并标记答案来源
4. **Given** 复盘点已创建, **When** 用户查看复盘列表, **Then** 可以看到问题摘要、答案来源标记和已复盘状态

---

### User Story 2 - 标记复盘状态 (Priority: P1)

用户可以对每个复盘点进行"已复盘"标记，表示该问题已经复习掌握。支持批量标记和筛选查看。

**Why this priority**: 复盘状态追踪是用户衡量复习进度的核心方式

**Independent Test**: 可以通过标记一个复盘点为已复盘，验证状态变更和列表筛选功能

**Acceptance Scenarios**:

1. **Given** 用户查看复盘点列表, **When** 点击某个复盘点的"标记已复盘"按钮, **Then** 该点状态变为已复盘
2. **Given** 存在已复盘和未复盘的复盘点, **When** 用户选择筛选条件, **Then** 列表按状态过滤显示

---

### User Story 3 - 每日考核点生成 (Priority: P2)

系统每天自动生成一个考核点，从用户的复盘点库中随机抽取一个未复盘的问题，提醒用户进行复习。

**Why this priority**: 帮助用户定期回顾，强化记忆，但依赖于已有复盘点数据

**Independent Test**: 可以通过触发每日考核功能，验证系统从复盘点中随机选择一个问题展示

**Acceptance Scenarios**:

1. **Given** 用户登录系统, **When** 首次进入每日考核页面, **Then** 系统按需生成并显示一个从复盘点中随机抽取的问题
2. **Given** 用户已完成当日考核, **When** 再次进入考核页面, **Then** 提示今日考核已完成并显示已完成的考核内容
3. **Given** 用户复盘点库为空, **When** 进入每日考核页面, **Then** 提示用户先创建复盘点

---

### User Story 4 - 每日面试题练习 (Priority: P2)

系统每天生成一个AI智能体工程师岗位相关的面试问题，用户进行回答，系统记录用户的回答内容。

**Why this priority**: 持续练习新问题有助于扩展知识面，但需要AI持续生成能力

**Independent Test**: 可以通过触发新面试题生成，验证问题展示和用户回答保存功能

**Acceptance Scenarios**:

1. **Given** 用户进入每日练习页面, **When** 首次访问当天, **Then** 系统按需生成一个AI智能体工程师岗位面试问题
2. **Given** 用户看到面试问题, **When** 输入答案并提交, **Then** 答案被保存并与问题关联
3. **Given** 用户已完成当天练习, **When** 再次进入练习页面, **Then** 显示已完成的练习内容和答案

---

### User Story 5 - 每周深度分析 (Priority: P3)

系统每周根据用户的复盘点新增情况和练习回答，生成分类分析报告，包含按技能分类的统计数据、薄弱点识别和具体改进建议。

**Why this priority**: 深度分析需要积累数据，属于进阶功能，但能提供有针对性的学习指导

**Independent Test**: 可以通过触发周报生成，验证系统输出包含分类统计和改进建议的完整报告

**Acceptance Scenarios**:

1. **Given** 用户有本周的复盘记录和练习回答, **When** 触发周度分析, **Then** 系统生成包含按技能分类统计的报告
2. **Given** 周报已生成, **When** 用户查看报告, **Then** 可以看到薄弱点识别和具体改进建议
3. **Given** 周报已生成, **When** 用户查看报告, **Then** 可以看到本周与上周的数据对比趋势

---

### User Story 6 - 技能边界管理 (Priority: P2)

用户可以定义和管理AI智能体工程师岗位的必备技能清单，界定自己的学习范围和重点。

**Why this priority**: 明确技能边界有助于聚焦学习方向

**Independent Test**: 可以通过添加/编辑技能项，验证技能列表的管理功能

**Acceptance Scenarios**:

1. **Given** 用户进入技能管理页面, **When** 添加新技能项, **Then** 技能被保存到技能清单
2. **Given** 技能清单已存在, **When** 用户编辑技能优先级, **Then** 优先级设置被更新

---

### User Story 7 - 数据导出为Markdown (Priority: P2)

用户可以将单个复盘点导出为独立的Markdown文件，便于本地保存、分享和整理。

**Why this priority**: 单个导出更灵活，用户可按需选择导出内容

**Independent Test**: 可以通过点击某个复盘点的导出按钮，验证生成独立的MD文件

**Acceptance Scenarios**:

1. **Given** 用户查看某个复盘点详情, **When** 点击"导出为MD", **Then** 系统生成该复盘点的独立Markdown文件供下载
2. **Given** 导出的MD文件, **When** 用Markdown编辑器打开, **Then** 包含问题、答案、参考资料链接，格式正确可读
3. **Given** 用户在复盘点列表页, **When** 选中多个复盘点并点击批量导出, **Then** 系统为每个复盘点生成独立的MD文件并打包下载

---

### Edge Cases

- 当复盘点库为空时，每日考核如何处理？应提示用户先创建复盘点
- AI生成答案失败时如何处理？应显示错误提示并允许重试
- 导出数据量过大时如何处理？应分批导出或提示数据量限制
- 用户输入的问题过于模糊时，AI如何生成有意义的答案？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-000**: 系统 MUST 提供用户注册和登录功能，支持用户名密码认证
- **FR-000b**: 系统 MUST 实现数据隔离，每个用户只能访问自己的复盘点、练习记录和报告
- **FR-001**: 系统 MUST 提供AI对话界面，支持用户输入面试问题
- **FR-001b**: 系统 MUST 支持两种答案获取方式：AI生成答案和手动输入答案
- **FR-001c**: 系统 MUST 标记每个复盘点的答案来源（AI生成/手动输入）
- **FR-002**: 系统 MUST 将问答对保存为复盘点，并支持查看复盘点列表
- **FR-003**: 系统 MUST 允许用户标记复盘点为"已复盘"状态
- **FR-004**: 系统 MUST 每天从复盘点中随机抽取一个问题作为考核点
- **FR-005**: 系统 MUST 每天生成一个AI智能体工程师岗位的面试问题供用户练习
- **FR-006**: 系统 MUST 记录用户对练习问题的回答
- **FR-007**: 系统 MUST 每周生成用户知识薄弱点分析报告
- **FR-007b**: 报告 MUST 包含按技能分类的统计数据、薄弱点识别和具体改进建议
- **FR-007c**: 报告 MUST 包含本周与上周的数据对比趋势
- **FR-008**: 系统 MUST 提供技能清单管理功能，支持添加、编辑、删除技能项
- **FR-009**: 系统 MUST 支持将单个复盘点导出为独立的Markdown文件
- **FR-009b**: 系统 MUST 支持批量导出多个复盘点为独立MD文件（打包下载）
- **FR-0010**: AI生成的答案 MUST 包含技术解答和相关在线资料链接
- **FR-0011**: 系统中流程相关的回复 MUST 以Mermaid格式呈现

### Key Entities

- **复盘点 (ReviewPoint)**: 面试问答对，包含问题、答案内容、答案来源（AI生成/手动输入）、参考资料链接、复盘状态、创建时间
- **练习题 (PracticeQuestion)**: 每日面试练习题，包含问题内容、用户答案、生成时间
- **考核点 (DailyChallenge)**: 每日考核记录，包含关联的复盘点、完成状态、考核日期
- **周报 (WeeklyReport)**: 每周分析报告，包含分析内容、统计日期、按技能分类的统计数据、薄弱点列表、改进建议、与上周对比趋势
- **技能项 (SkillItem)**: 岗位必备技能，包含技能名称、描述、优先级、边界说明

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可以在30秒内完成一个复盘点的创建（输入问题并获得AI回复）
- **SC-002**: 系统每天准时生成考核点和练习题，用户可在首页直接看到
- **SC-003**: 导出的Markdown文件可在任意标准Markdown编辑器中正确渲染
- **SC-004**: 用户每周可获得一份包含至少3个具体改进建议的分析报告
- **SC-005**: 技能清单支持至少20个技能项的管理
- **SC-006**: AI生成的答案包含至少1个有效的在线资料链接

## Assumptions

- 用户具备基本的计算机操作能力，能够使用Web浏览器
- 用户将自行配置AI服务的API访问密钥
- 系统主要面向AI智能体工程师岗位的面试准备
- 每日考核和练习题在用户访问对应页面时按需生成
- 周度分析基于最近7天的数据进行
- 数据存储在本地，支持多用户但部署在同一实例
- 系统为本地部署使用，用户密码需加密存储

## Implementation Phases

### Phase 1 - 前端页面评审（当前阶段）

**目标**: 先完成所有前端页面开发，供用户评审UI/UX设计，确认交互流程后再进行后台开发

**交付内容**:
- 所有页面的Vue3组件和布局
- 页面间的路由和导航
- UI样式和交互效果（使用Mock数据）
- 响应式设计适配

**不包含**:
- 后台API对接
- 数据库操作
- AI服务集成
- 用户认证逻辑

**评审页面清单**:
1. 登录/注册页面
2. 主仪表盘（每日考核、练习入口）
3. 复盘点列表页面
4. 复盘点详情/编辑页面
5. AI对话创建复盘点页面
6. 每日考核页面
7. 每日练习页面
8. 周度分析报告页面
9. 技能管理页面
10. 数据导出页面

### Phase 2 - 后台开发与集成

**目标**: 基于Phase 1确认的页面设计，开发后台API并完成前后端对接

**交付内容**:
- FastAPI后台服务
- SQLite数据库设计与操作
- LangChain DeepAgents集成
- 用户认证与数据隔离
- 前后端API对接
